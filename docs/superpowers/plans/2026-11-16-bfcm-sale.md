# BFCM 2026 Sale Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put every active product at 30% off its original price via compare-at pricing, and launch a black BFCM homepage banner + header marquee, with a clean exact revert on Dec 1.

**Architecture:** A small Python CLI (`scripts/bfcm-2026/`) computes sale prices with pure, unit-tested functions and reads/writes variants through `shopify store execute` (same pattern as `.claude/seo-audit/apply.py`), snapshotting every variant before writing. Storefront changes are JSON-only edits to `templates/index.json`, `sections/header-group.json` and `config/settings_data.json`, shipped as one PR whose merge to main is the launch.

**Tech Stack:** Python 3 stdlib only (`decimal`, `unittest`, `subprocess`, `json`), Shopify Admin GraphQL via global Shopify CLI 4.9.4 (`shopify store execute`), Horizon theme JSON, `npx @shopify/cli@4.6.0 theme dev` / `theme check`.

**Spec:** `docs/superpowers/specs/2026-11-16-bfcm-sale-design.md`

## Global Constraints

- Store: `arttitudes.myshopify.com`. Scope: products with `status:active` only.
- Pricing rule per variant: `original = compareAt if compareAt > price else price`; `target = floor(original × 0.70)` to whole dollars; `new_price = min(price, target)`; `new_compareAt = original`; skip if unchanged. Never raise a price.
- Use `decimal.Decimal` for all money; never float.
- Every write is preceded by a full backup of every active variant's `price` + `compareAtPrice`. Backups and logs go to `~/Development/arttitude-store-work/bfcm-2026/` (outside the repo/worktree, durable). Never commit backups.
- Sale window: now → **Dec 1 2026, 00:00 store time** (end of Cyber Monday).
- Copy (exact): banner headline `30% OFF EVERYTHING`; banner subline `Black Friday through Cyber Monday · ends Nov 30`; CTA `Shop the sale` → `shopify://collections/all`; marquee `BLACK FRIDAY · 30% OFF EVERYTHING · ENDS CYBER MONDAY` → `shopify://collections/all`.
- Look: black `#000000` background, white type; headline in the heading font (DM Sans 900), subline in body font (Space Mono). No new fonts, no new Liquid unless a setting can't express it.
- Merging to main = production deploy. Never `theme push`. The owner merges; the agent never merges.
- Live writes to the store (Task 4 apply, Task 5 rollback) run only after the owner has seen the dry-run summary and said go.

## Review Focus

1. **Junk compare-at** (`compareAt <= price`, e.g. equal values left over from old sales) — must be treated as "no original"; the variant gets compare-at = current price. → test in Task 1.
2. **Re-running after a partial failure** — a variant already at its sale price must produce no change, so `apply` is safely re-runnable. → test in Task 1 + Task 2.
3. **Pagination / truncated variants** — more than one page of products, or a product whose fetched variants < `variantsCount`, must stop the run rather than silently skip variants. → test in Task 2.
4. **Hand edits during the sale** — at rollback, a variant whose live price ≠ the price we set is reported and skipped (not overwritten) unless `--force`; variants not in the backup (new products) are reported, untouched. → test in Task 2.
5. **Market fixed prices** — if any price list has fixed prices, those variants won't follow the base price change; the fetch must print a warning with the count so the owner decides. → covered in Task 2 fetch output, checked in Task 4.

### Task 1: Sale price math

**Files:**

- Create: `scripts/bfcm-2026/pricing.py`
- Test: `scripts/bfcm-2026/test_pricing.py`

**Interfaces:**

- Produces: `sale_price(price: Decimal, compare_at: Decimal | None) -> tuple[Decimal, Decimal] | None` — returns `(new_price, new_compare_at)` or `None` when no write is needed. `DISCOUNT = Decimal("0.70")`.

- [ ] **Step 1: Write the failing tests** (`unittest`, values in `Decimal`)

```python
def test_full_price_item(self):        self.assertEqual(sale_price(D("135.00"), None), (D("94"), D("135.00")))
def test_already_marked_down(self):    self.assertEqual(sale_price(D("101.25"), D("135.00")), (D("94"), D("135.00")))
def test_deeper_than_30_untouched(self): self.assertIsNone(sale_price(D("113.75"), D("175.00")))   # target 122 > 113.75
def test_junk_compare_at_equal(self):  self.assertEqual(sale_price(D("95.00"), D("95.00")), (D("66"), D("95.00")))
def test_junk_compare_at_lower(self):  self.assertEqual(sale_price(D("95.00"), D("80.00")), (D("66"), D("95.00")))
def test_idempotent(self):             self.assertIsNone(sale_price(D("94"), D("135.00")))
def test_zero_price_skipped(self):     self.assertIsNone(sale_price(D("0.00"), None))
def test_floor_to_zero_skipped(self):  self.assertIsNone(sale_price(D("1.00"), None))   # floor(0.70) = 0 → never set a $0 price
def test_never_raises(self):           # property over a grid of price/compare pairs
    for p in range(1, 400):
        for c in (None, p, p + 20, p * 2):
            r = sale_price(D(p), None if c is None else D(c))
            if r: self.assertGreater(r[0], 0); self.assertLessEqual(r[0], D(p)); self.assertGreaterEqual((1 - r[0] / r[1]), D("0.30"))
```

      Expected: FAIL / ImportError on `pricing`.

- [ ] **Step 3: Implement `sale_price` in `pricing.py`** — floor via `quantize(Decimal("1"), rounding=ROUND_FLOOR)`.

### Task 2: Store CLI — fetch, plan, apply, verify, rollback

**Files:**

- Create: `scripts/bfcm-2026/bfcm.py`
- Test: `scripts/bfcm-2026/test_bfcm.py` (offline, fixture dicts only — no store calls)

**Interfaces:**

- Consumes: `sale_price` (Task 1).
- Produces (all pure except the I/O ones marked ⚡):
  - Snapshot shape: `{"taken_at": iso, "timezone": str, "products": [{"id", "handle", "title", "variantsCount", "variants": [{"id", "price", "compareAtPrice"}]}]}` (prices as strings, as the API returns them).
  - `build_plan(snapshot) -> list[dict]` → one entry per product with changes: `{"productId", "handle", "variants": [{"id", "price", "compareAtPrice", "old_price", "old_compareAtPrice"}]}`. Raises `ValueError` if any product has `len(variants) != variantsCount`.
  - `summarize(plan, snapshot) -> str` — products/variants total, changed, skipped-deeper, junk-compare-at count, min/max/median resulting discount %, 10 sample rows.
  - `build_rollback(backup, live, sale_plan) -> tuple[list[dict], list[str]]` → (writes restoring backup values, report lines for hand-edited variants and variants absent from the backup).
  - ⚡ `fetch() -> snapshot` — `shop { ianaTimezone }`; `products(first: 50, after:, query: "status:active") { pageInfo { hasNextPage endCursor } nodes { id handle title variantsCount { count } variants(first: 100) { nodes { id price compareAtPrice } } } }`; also `priceLists(first: 20) { nodes { name currency fixedPricesCount } }` → print WARNING if any `fixedPricesCount > 0`.
  - ⚡ `write(plan_entries)` — `productVariantsBulkUpdate(productId:, variants: [{id, price, compareAtPrice}])` per product, collect `userErrors`, partial log every 20 products, sleep 0.3s between calls. Reuse `run()` retry logic from `.claude/seo-audit/apply.py` (copy the function; that file is untracked).
- CLI (`python3 -I scripts/bfcm-2026/bfcm.py <cmd>`), all files under `OUT = ~/Development/arttitude-store-work/bfcm-2026/`:
  - `plan` → fetch, save `snapshot-<ts>.json`, save `plan-<ts>.json`, print summary. Writes nothing to the store.
  - `apply <plan-file>` → fetch again and save as `backup-BEFORE-SALE-<ts>.json` (first time only; later runs save `backup-<ts>.json`), rebuild plan from the fresh fetch, refuse if it differs from `<plan-file>` by more than the already-applied variants, then `write`.
  - `verify <plan-file>` → fetch; every planned variant must equal planned price/compare-at; print `OK n/n` or the mismatches; exit 1 on mismatch.
  - `rollback <backup-file> [--force]` → fetch live, `build_rollback`, print report, write, then verify against the backup.

- [ ] **Step 1: Write failing tests** for the pure functions, using a fixture snapshot of 3 products: A full-price (2 variants, 135.00/none and 150.00/none), B marked down (101.25/135.00), C deeper (113.75/175.00) plus one junk variant (95.00/95.00).
  - `test_plan_counts`: plan has products A and B and C's junk variant only; A's variants → 94/135.00 and 105/150.00.
  - `test_plan_idempotent`: applying the plan's values into the snapshot and rebuilding → `[]`.
  - `test_truncated_variants_raises`: product with `variantsCount: 3` but 2 variants → `ValueError`.
  - `test_rollback_restores`: live = sale values → writes restore exact backup strings (e.g. B back to 101.25/135.00, A back to compareAtPrice `None`).
  - `test_rollback_skips_hand_edit`: one live variant price ≠ planned sale price → not in writes, in report; with `force=True` → in writes.
  - `test_rollback_reports_new_product`: live product absent from backup → in report, not in writes.
- [ ] **Step 2: Run** `python3 -I -m unittest discover -s scripts/bfcm-2026 -v` → new tests FAIL.
- [ ] **Step 3: Implement pure functions + CLI + I/O in `bfcm.py`.**
- [ ] **Step 4: Run tests** → all PASS.
- [ ] **Step 5: Read-only smoke test against the store:** `python3 -I scripts/bfcm-2026/bfcm.py plan` → expect ~187 products / ~952 variants, timezone printed, summary with min discount ≥ 30%, no ValueError. Paste the summary for the owner.
